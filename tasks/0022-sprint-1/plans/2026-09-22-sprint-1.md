## Goal

A Chrome MV3 extension whose dashboard scans the whole Watch Later playlist,
builds remove and protect rules over watch progress, channel, position,
duration, title, availability and Shorts, previews exactly what a run would
remove, and removes it in throttled batches with a log. Done when a real
playlist is cleaned following `docs/LIVE-CHECKLIST.md`.

Topic rules need a Data API key and are sprint 2 (#18, #19). Sprint 1 carries
the topic condition in the rule model so sprint 2 adds data, not a redesign.

## Context

- Design: `docs/ARCHITECTURE.md`. Research and open questions:
  `docs/RESEARCH.md`. Source being ported: `reference/upstream/`.
- Stack mirrors the Amazon order extension: plain JS, no build step,
  `node --test` plus jsdom for units, Playwright for the browser harness.
  Node 22 and Playwright 1.56 are already installed on this host.
- Everything that talks to YouTube is ported from upstream, which is proven
  against the live site. Everything that decides what to remove is new.

## Working conventions

These exist so each issue can be picked up cold, from the repository alone.

- **Numbers line up.** Issue #N is task folder `tasks/000N-<slug>/` and branch
  `feature/000N-<slug>`. This sprint's own folder is 0022, after its tracking
  issue.
- **Per issue loop:**
  1. Take the lowest numbered open issue in the earliest unfinished wave that
     has no `blocked` label.
  2. Create its task folder with a plan written from the issue's scope and
     acceptance, now informed by whatever earlier issues found. Detailed step
     plans are written per issue at that point, not here, because #3 will
     change the details of #6, #7 and #16.
  3. Branch, then test first: failing test, watch it fail for the right
     reason, implement, green.
  4. `npm test` green. For #11 onward, also the relevant manual or browser
     check.
  5. Progress log entry per step, including what did not work.
  6. PR with `Closes #N`, each acceptance box shown with its command and real
     output. Code commits and task file commits kept separate.
  7. Review written to the task's `reviews/`, then a regular merge commit.
  8. Remove `blocked` from any issue whose last dependency just closed, and
     tick it in #22.
- **Upstream ports come in two commits:** behaviour-identical port first,
  restructure second, so the port diffs cleanly against `reference/upstream/`.
- **Safety issues** (label `safety`) get their safety acceptance criteria
  written as tests before any implementation code.

## Risks

| Risk | Effect | Handling |
|---|---|---|
| Watch Later items moved to `lockupViewModel` | Upstream parser misses every item | #3 answers this before #6 starts; #6 supports whichever shape the capture shows, or both |
| No added-at date in InnerTube | Age rules are position-only | Position under a verified sort is the sprint 1 answer; #20 imports Takeout dates in sprint 2 |
| Batch removal rate-limited | Runs stop early | Small default batches, pause, stop on first 429 with the log intact; #17 measures the real limit |
| Main world bridge abused by another page script | Unwanted removals | Nonce check in #11, and the remover only accepts a plan built from a preview (#9) |
| YouTube changes an endpoint mid-sprint | Scan or removal fails | Typed errors surface it; fixtures pin the last known shape; the fake in #16 keeps the rest testable |
| Storage quota with big playlists | Lost scan or log | #10 degrades to a warning, evicts oldest logs first |
