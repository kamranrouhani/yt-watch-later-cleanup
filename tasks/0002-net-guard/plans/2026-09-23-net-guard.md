# The network chokepoint and the guard tests

- **Issue:** #2
- **Branch:** `feature/0002-net-guard`
- **Written:** 2026-09-23 14:07, on `main` at `ee6cd1b`
- **Supersedes:** nothing

## Goal

`src/core/net.js` as the only module allowed to call `fetch`, with an origin
allowlist, plus the two guard tests that make the local-only rule structural:
`test/no-network.test.js` scanning every shipped file, and
`test/wiring.test.js` pinning manifest wiring.

## Decisions

- **`net.js` API:** `createNet(allowedOrigins)` returns `{ fetch }` bound to
  the allowlist. `fetch(url, init)` resolves the URL, rejects anything whose
  origin is not in the list before any request is sent, and otherwise calls
  global `fetch` with `credentials: 'include'`. A rejected call throws a
  `TypeError` with the disallowed origin in the message, like a real fetch
  would for an invalid URL.
- **Allowlist entries are origins** (`https://www.youtube.com`), and matching
  is by `new URL(url).origin`, exact equality, so `https://www.youtube.com.evil.io`
  and scheme swaps fail.
- **The default allowlist lives in `constants.js`**, `YOUTUBE_ORIGIN` and
  `DATA_API_ORIGIN`, and `net.js` exports `defaultNet` built from it. #18
  adds the Data API origin to the default only when a key is configured; the
  guard test tolerates both origins from the start, per the issue.
- **Shipped files** for the scan: `background.js`, `manifest.json`,
  `dashboard/**`, `src/**`. Not scanned: `reference/`, `test/`, `tools/`,
  `tasks/`, `docs/`, `scripts/`, `node_modules/`, `.github/`. `tools/capture.js`
  calls `fetch` on purpose and is dev tooling, not shipped.
- **Scan patterns:** `fetch(`, `XMLHttpRequest`, `sendBeacon`, `WebSocket`,
  `EventSource`, `import(` (dynamic import; `require(` is Node-only and the
  wrapper's `module.exports` line does not contain it as a call), `new Worker(`
  outside `src/core/net.js`. Plus any `https://` URL whose host is not
  `www.youtube.com` or `www.googleapis.com`.
- **String literal handling:** a shipped file mentioning `https://evil.example`
  in a string still fails, because the point is that no other origin is ever
  named. `dashboard.html` and `dashboard.css` are scanned too, for origin
  references only.
- **`wiring.test.js`:** every path `manifest.json` references exists
  (background service worker, action default paths, icons when present, web
  accessible resources, content scripts when they arrive); every `.js` under
  `src/core` that the dashboard loads is listed in `dashboard.html` script
  tags (the wiring that exists today); and the manifest declares no
  duplicates in `permissions`, `host_permissions`, or `content_scripts`
  matches. The check is written to accept today's manifest and to fail when
  #11 adds content scripts without listing their files.
- **`fetch(` matching must not match `prefetch(` or `myfetch(`**: the regex
  requires a word boundary before `fetch`.

## Steps

### Step 1: Plan

This file and a seeded progress log, one commit.

### Step 2: Safety tests first

`test/net.test.js`: rejects `https://example.com/path` with a `TypeError`
naming the origin; allows `https://www.youtube.com/youtubei/v1/browse` and
`https://www.googleapis.com/youtube/v3/videos` through to a stubbed global
`fetch` that records the call; relative URLs throw (no origin to check);
`https://www.youtube.com.evil.io/` throws; `http://www.youtube.com/` throws
(scheme swap); `credentials: 'include'` is forced on allowed calls.

Expected: `Cannot find module '../src/core/net.js'`.

### Step 3: `src/core/net.js`

The module, in the WLCore wrapper. `npm test` green. Bites: drop the
allowlist check (allow test still passes but the reject test fails), accept
`startsWith` matching instead of origin equality (evil suffix host passes,
test fails), drop the credentials forcing.

### Step 4: `test/no-network.test.js`

Scan as above. Prove it bites: append `fetch('https://example.com/x')` to
`dashboard/dashboard.js`, expect failure naming the file and the reason;
revert. Append `const s = new WebSocket('wss://x.io')`, expect failure;
revert. Write `https://evil.io/x` in a string in `background.js`, expect
failure; revert. Prove exclusion: none of `tools/`, `reference/`, `test/`
appear in a failure when the same violations are planted there (planted in
scratch copies via a parameterised root, not in the repo).

### Step 5: `test/wiring.test.js`

As above. Prove it bites: point `background.service_worker` at a missing
file in a scratch manifest copy, expect failure; add a duplicate permission
in a scratch copy, expect failure.
