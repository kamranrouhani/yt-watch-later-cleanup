# Rework round 1: the default-sleep test also pins the await

- **Supersedes:** nothing in force. `2026-09-24-remover-sleep-flake.md`

  reasoning is wrong and is superseded by this file.

## Why

Review round 1 (reviews/2026-09-24-0820-review-r1.md, one numbered finding):
the timer-stub rewrite proves the default sleep schedules the pause but no
longer proves it is awaited. Mutation: the batch loop's `await
sleep(pauseMs)` becomes `sleep(pauseMs)`. The whole suite stays green under
that mutation, while the old wall-clock test went red on exactly it. The
await is the rate limit between edit batches, and the card's hard rule
forbids a test that passes without the default sleep running, which
includes running to completion.

## Goal

The default-sleep test asserts both halves of "the default sleep ran":

1. the schedule half, already approved: with no `sleep` injected, `run()`
   called the real `setTimeout` exactly once with `5`, the `pauseMs`.
2. the await half, new: batch 2's edit call happens only after that timer's
   promise resolved, which proves the loop awaited it.

No wall-clock reads. `src/core/remover.js` still does not change.

## Decisions

- **The stub's setTimeout is a gate the test settles.** The stub records
  the requested delay, starts the real timer, and returns a promise that
  resolves when the timer has fired and the test has resolved a release
  it holds. The gate also carries a `settled` flag, set synchronously when
  both conditions are met.

- **The fake asserts the gate had settled before batch 2.** The fake
  innertube reads `settled` synchronously at entry to its second
  `editPlaylist` call and sets a flag; the test asserts that flag. No
  timer race: the read happens before any await, and the flag can only be
  true if the loop awaited the gate promise before starting batch 2.
  Under the unawaited mutation the second call is entered while the
  test still holds the release unresolved, the flag stays false, the run
  finishes "complete" and the test goes red on the flag with a clean
  message.

- **`src/core/remover.js` does not change.** The card allows a code change
  only if the default is not observable otherwise. The gate construction
  observes both the schedule and the await, so the remover keeps every
  behaviour, safety included.

- **The timer stub stays scoped and restored in `finally`**, exactly as
  approved in round 1.
