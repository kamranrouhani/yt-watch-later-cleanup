## The defect

A third bite, not covered by the implementer, shows a coverage
regression. Change the batch loop from `await sleep(pauseMs)` to
`sleep(pauseMs)` (call kept, await dropped) in `src/core/remover.js`:

- New test: green. `# pass 14` `# fail 0`. Nothing in the suite goes
  red. `search_files` over `test/remover.test.js` confirms no other test
  exercises the default sleep path.
- The old wall-clock test against the same mutation: `not ok 12 - a
  default sleep is used when none is injected` (run from
  `git show origin/main:test/remover.test.js` in a transient probe file,
  removed after). So the rewrite dropped a case the old test caught:
  the default sleep being scheduled but not awaited.

Why it matters: the await is the pause between edit-batch calls that
keeps the remover from hammering YouTube. The card body's hard rule is
"do not weaken the test into something that passes without the default
sleep: the prove-it-bites step must show it going red when the default
sleep is removed." An unawaited default sleep passes the whole suite
now, which is exactly the weakening the card forbids. The pre-merge
self review's claim "awaiting is covered by the run finishing after the
schedule" is not true: a floating promise resolves nothing and the run
finishes regardless.

The wall-clock precision is fixable without giving up the await
coverage. Either assert the awaited duration (resolve the stubbed timer
through a manually controlled clock, or record resolve times), or keep
the timer-stub schedule assertion and add the await check: have the
stub return a promise the test settles, or assert inside `onBatch` that
the previous pause's promise completed before the next batch's edit
call. One of those, or an equivalent construction, makes both bites red
again.
